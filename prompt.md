Development Rules
Never use placeholder text when the real content can be extracted from HostingSpell.com.
Reuse existing assets and branding.
Prefer Astro-native features over client-side JavaScript.
Every component must be reusable and documented.
Maintain a consistent visual language across the entire site.
Keep dependencies minimal and justify any non-essential package.
Commit work in logical milestones if version control is available.
Definition of Done

The project is complete only when it:

Faithfully preserves the HostingSpell brand while presenting it in a modern, premium design.
Achieves excellent Core Web Vitals and near-perfect Lighthouse scores.
Is fully responsive across mobile, tablet, and desktop.
Meets WCAG AA accessibility standards.
Has comprehensive SEO metadata and structured data.
Uses a scalable, maintainable component architecture.
Is production-ready with no placeholder content, dead links, console errors, or unnecessary dependencies.

The final result should make HostingSpell feel like a modern, world-class hosting provider while retaining its existing identity, content, and customer trust.
